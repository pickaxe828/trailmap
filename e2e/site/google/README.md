# Google Search capture fixtures

These are sanitized local reconstructions, not Google pages replayed from the network. A signed-out fetch of `/search?udm=50` returned a JavaScript interstitial, not a usable conversation. The fixtures retain the observed reply boundary and composer from the publicly documented reverse engineering in [Chibbit-99/google-ai-mode-scraper](https://github.com/Chibbit-99/google-ai-mode-scraper/blob/8c3d40d14f7215822614cbee8ea06266332023fa/js/v1.0.0.js) (`Ask anything`, `Send`, `AI Mode reply for …`, `data-complete`), and the `main-col` and citation structure recorded by [tomxposed/google-ai-mode-scraper](https://github.com/tomxposed/google-ai-mode-scraper/blob/37839f5ec75a5255137508f3f9e289c9619b3d4e/src/scraper.ts). The questions, replies, links, Overview and page script are synthetic. There are no account identifiers, tokens or remote scripts.

The extractor unit tests read the snapshots as HTML, without running scripts. Chromium tests fulfill the Google routes from these files. The landing form exercises the initial document change; the conversation fixture exercises an existing untyped reply, a same-document follow-up, a streamed completion, and an incomplete layout without answer text.
